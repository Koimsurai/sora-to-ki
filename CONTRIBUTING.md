# Contributing

Thanks for wanting to help. sora-to-ki takes **issues, not pull requests**.

## Issues are welcome

- **Bugs**: what you did, what you expected, what happened. The version (`SORA_TO_KI_VERSION` or the image tag), the browser, and anything from `docker compose logs backend-rs` help a lot.
- **Setup trouble**: if the README or the setup wizard left you stuck, that is a bug in the docs. Say where you got lost.
- **Ideas**: describe the problem you want solved rather than the code you would write. Customisation here works as hand-tuned presets to choose from, not open-ended settings, so a request may be answered with a different shape than the one asked for.
- **Translations**: a wrong or awkward phrase in any of the five languages is worth an issue. Quote the text and say where it appears.

## Why no pull requests

The code is AGPL-3.0 and its copyright stays with one person. That keeps the licence simple to enforce and leaves room to change it later without tracking down every contributor. It also keeps the design consistent: most changes touch how the site looks and moves, and those are decided case by case.

If you have already written a fix, link it from the issue. It may well be reimplemented from your description.

## Security

Please do not open a public issue for a vulnerability. Report it privately through [GitHub's security advisories](https://github.com/Koimsurai/sora-to-ki/security/advisories/new) instead.
